## 1. Stack

**Framework**
- Web: **Next.js 14.2.18** (App Router) + React 18.3.1
- API: **NestJS 10.4.7** on Node ≥20 (Express platform)

**Language**
- TypeScript 5.6.3 throughout
- Strict mode: **yes** — base tsconfig has `"strict": true`, `"noUncheckedIndexedAccess": true`, `"noImplicitOverride": true`, `"verbatimModuleSyntax": true`, `"isolatedModules": true`

**Package manager + Node**
- pnpm 9.12.0 (declared in root `package.json`)
- pnpm workspace lockfile v9
- Node engines: `>=20`
- Turborepo 2.3.0 orchestrates `dev` / `build` / `lint` / `typecheck` / `test`

**Monorepo layout**
- `apps/web` — Next.js frontend
- `apps/api` — NestJS backend
- `packages/types` — shared zod schemas + TS types (workspace `@peerahat/types`)
- `packages/ui` — shared React component library (workspace `@peerahat/ui`)
- `packages/config` — shared tsconfig + tailwind preset + eslint config

## 6. State & Data

### State management
- **TanStack React Query** is the only client-side store (`apps/web/app/providers.tsx`).
- `staleTime: 60_000`, `refetchOnWindowFocus: false`, `retry: 1`.
- `queryCache.onError` → Sonner toast.
- `mutationCache.onError` → only toasts when `mutation.meta.toast` is truthy.
- **No Redux / Zustand / Context for app state.**
- Auth state lives in Supabase SSR cookies; the SiteNav subscribes to `supabase.auth.onAuthStateChange` for live updates.

### API client setup — `apps/web/lib/api-client.ts`
- **Base URL**: `process.env.NEXT_PUBLIC_API_BASE_URL ?? "http://localhost:3001/api"`
- **Auth header**: `Bearer <token>` on every request.
  - Server callers pass a snapshotted token via `createApiClient({ accessToken })`.
  - Browser callers omit the arg; the client fetches the live Supabase session token automatically.
- **401 transparent refresh** (browser only): on 401 without explicit token, calls `supabase.auth.refreshSession()` once and retries.
- **Error handling**: throws an object with `{ statusCode, message, code?, details? }` (see `ApiError` in `packages/types/src/api.ts`).
- **`asNotFound(promise)`** helper: routes 404s to Next.js `notFound()` from Server Components.
- **Multipart upload helper** mirrors the 401-refresh path for presigned PUT flows.
- Every endpoint is keyed in a single typed object `API_PATHS` (see `packages/types/src/api.ts`).

## 7. Inconsistencies & Fragility

**Duplicate components**
- `apps/web/components/main-shell.tsx` and `apps/web/components/main-wrapper.tsx` are functionally identical. The layout uses `main-wrapper`; `main-shell` is dead code.
- `apps/web/components/cloud-background.tsx` and `apps/web/components/scroll-video-background.tsx` are legacy from prior landing iterations and are imported nowhere.

**Mixed styling approaches**
- `globals.css` defines parallel `.landing-*` utility classes that duplicate what Tailwind utilities + the design tokens already express (e.g. `.landing-btn-grape` is just `bg-dusty-grape px-7 py-3.5 rounded-[14px] …`). **Status (2026-05-20):** every `.landing-*` rule is now grouped with a page-agnostic `.brand-*` alias on the same rule — landing markup still works, but new code should reach for the brand names.
- `landing/Nav.tsx` and `landing/Hero.tsx` use Tailwind tokens directly with arbitrary `[...]` values (`rounded-[16px]`, `text-[24px]`) instead of the design-system `rounded-lg`, etc.

The inline Hero / Nav.tsx classes still exist and aren't yet routed through `Button`.

**Color tokens not in palette**
- `apps/web/app/layout.tsx`: `themeColor: "#4f46e5"` (indigo) — predates the violet palette migration.
